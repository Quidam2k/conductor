Conductor · build v78

What's new

What changed in each build, newest first. Your build number is at the bottom of the app's home screen.

← Open Conductor · Getting Started Guide

v79 2026-11-25 latest

  • Opens with no signal from the Home Screen. The app now keeps a copy of its start page, so the icon opens it offline even if you first visited through another link. The “Try It Now” demo link also opens offline.
  • Updates arrive sooner. After we publish a new build, a phone that already has the app shows it on the second time you open it. Before, it could keep showing the old screens for about ten minutes.
  • No more stuck downloads. A failed download is no longer saved and served again later. Voice pack downloads are no longer kept in the app’s offline copy, so a corrected pack reaches you.
  • Install voices checks the file. If the download is not the pack the button names, the button says “That download is a different pack” (or “Not a valid pack”) and nothing is installed.
  • A mistyped address on the site now shows a short “Page not found” page with links back to the app.
  • A sharper Home Screen icon on iPhone.

v78 2026-11-25

  • Joining late works with repeats. Go Live now counts every round of a repeating event, so you can join one that is still running. If every cue has already passed but the event has not ended, the preview says “This event already ran” instead of offering a rerun. An old event that has ended can still be restarted on your phone only, and the question says so.
  • Reloading keeps your event. An event you opened by pasting, scanning, beaming, from a file or from the demo now comes back on the preview after a reload or an app update. It never goes straight back into Live. A password-locked event asks for its password again (the password is never stored).
  • After a phone call. If the phone will not restart the pocket audio after an interruption, the app tries again a few times. If that still fails, Live shows “Track paused. Tap to resume.”
  • A new link asks before it stops you. Opening another event link during Live or Practice now asks first. “Keep going” carries on with the event you are in.
  • Long events run with the screen on. When the time from Go Live to the last cue is over 60 minutes, the phone no longer prepares pocket audio, because that much audio can crash an older phone. The check before Live says so, and the screen must stay on. The 60-minute figure is provisional until we have measured it on an older phone.
  • Repeats have a limit. One event can hold up to 5,000 cues. The editor now refuses a repeat that would go past that, and an event that reaches it says on the preview when its repeats stop. Before, the cues stopped without warning.
  • “Keep your screen on” shows every time it applies, not only the first time on a phone.
  • Mute silences recordings too. Before, recorded and robot-voice cues could still play while muted when the phone was not using pocket audio.
  • A “Get ready to” lead-in that would be cut off when Live opens just before a cue now plays whole, or is replaced by a short “Get ready”.

v77 2026-11-24

  • A typed event can no longer start at a time you did not mean. This build checks events written in the text format much more carefully. When something is wrong, the paste box or the editor says what, instead of quietly guessing.
  • Time zones. EST, EDT, ET, Eastern, and the Central, Mountain and Pacific labels now mean the city zone with daylight saving time (New York, Chicago, Denver, Los Angeles). Before, EST and MST were an hour off in summer, and EDT or PT quietly used the phone’s own zone. A label the app does not know, such as UTC+5, is refused with an example of one it does. In Arizona, write America/Phoenix.
  • Start times. A Start needs a clock time: a date on its own is refused (it used to land on the evening before). Impossible dates and times like February 30 or 25:00 are refused rather than moved to another day. A time that is skipped when the clocks go forward (2:30 AM on that night) is refused with a message; a time that happens twice when the clocks go back means the first one.
  • Numbers. Repeat:, Coda: and NotifyWindow: must be whole numbers, and Repeat is limited to 1,000 rounds. Coda: 0 (no rest between rounds) now works the same for you and for everyone you share with. Countdowns are capped at 10 seconds.
  • The preview tells you what it skipped. Lines the app did not understand are counted in a gold notice on the preview, with the first one shown, along with other notes such as an unknown tag. Times like 0:5 and 100:00 now work. A bracket at the start of a step is read as tags only when every word in it is a tag, so [Sit down] Everyone sits keeps its words.
  • The editor checks repeats. A repeat that ends before the event starts, or a repeat count under 2, now shows a message instead of turning repeat off without telling you.
  • Broken links say so. A damaged event link now shows “Could not read this event code” instead of an empty home screen.
  • Links you already shared keep opening as before. If you made a link from text that used EST or MST for a summer event, paste the text again and re-share it: the old link still has the old time.
  • The example events in the demos folder now start when their scripts say.

v76 2026-11-13

  • Password links are harder to guess. Someone who has a password link can try passwords against it on their own computer. Each try now costs them six times the work it did (600,000 key rounds, up from 100,000). New password links start with v1f_.
  • Everyone needs build v76 or later to open a new password link. An older build shows an error where the password box should be. Ask participants to refresh Conductor, or send them the app file along with the link.
  • Older password links still open. Links made before v76 start with v1e_. They open as before and are passed on unchanged, which means they keep the weaker lock. To get the stronger one, make a new link in the editor.
  • Short passwords get a warning. Under 8 characters, the app says the password is easy to guess and asks you to press again to use it. The lock is only as strong as the password, so a longer one matters more than anything else here.
  • The QR code, the link and the shared file for one event and password now all carry the same code. Before, every button press made a different one.
  • Opening and making a password link takes a little longer than before. We have not yet timed it on an older phone.

v75 2026-11-13

  • Fixed: a shared file could reveal a password-protected event. "Share File", "Download HTML" and "Share This App" used to copy what was on the screen into the file. A protected event's title, description and cue text, and the names of saved drafts, could be read by opening that file in a text editor. The file is now built from a clean copy of the app. If you sent a file of a protected event from an earlier build, treat what was in it as not protected.
  • Fixed: passing on a protected event removed its password. After you unlocked a protected event, the share buttons sent an unprotected copy. They now send the same locked code you received, so the next person needs the password too.
  • A protected event is shared under a plain name ("Conductor event", conductor-event.html) instead of its title, because the name shows in message previews and file lists.
  • A shared app file no longer carries the sender's text size.

v74 2026-11-12

  • Clear This Phone. A new button at the bottom of the home screen deletes everything Conductor has saved on the phone: drafts, imported packs, My Voice recordings and settings. It does not clear browser history or files you downloaded.
  • Navigate buttons show where they go. The coordinates are now shown next to each Navigate button, and no button is offered when an event's coordinates are not valid.
  • No remote stop, said plainly. The guide now says that a live phone can only be stopped on that phone, so agree a stop signal before the event.

v73 2026-11-10

  • Built-in robot voice for typed cues. Cue text with no recording (the cue word, "Get ready to…" heads-ups, clip lines) is now read by a robot voice that comes inside the app. It goes into the same pre-rendered track as the beeps and recordings, so typed cues should keep playing with the screen locked too. Practice, screen-on and locked all sound the same. The phone's own speech is only a fallback if the robot voice can't load. Recordings still sound much better. US English only for now; locked playback of the robot voice on iPhone is being tested now.
  • Fixed: the downloadable conductor.html and the "share this app" file could fail to start because of a build error. Both open properly again.
  • The app file is now about 2.1 MB (it was 0.8 MB), because the voice is inside it. That's still small enough to send by AirDrop or a messaging app.

v72 2026-11-10

  • Clearer, more careful wording about what's been tested. Locked-screen audio is marked as tested on iOS 18 (iOS 26 and longer events are being tested now); AirDrop / Quick Share hand-off is marked as not yet confirmed on every phone; privacy wording says plainly that a link is only as private as the way you send it.
  • Easier way to help test on iPhone: a "Help us test" link in the app's "What is this?" box, and new questions in the bug report form (system version, build, and how you opened the app).

v71 2026-10-27

  • Larger text no longer hides the bottom of the screen on Android (buttons and the Install voices / Manage Packs rows were off the bottom).
  • iPhone: confirmations (like "Start it 1 minute from now?") are now in-page, so Go Live no longer silently does nothing; Go Live and Go Back clear Safari's floating toolbar; a pasted event that iOS turned into Title:%20... is read correctly.
  • Start times now show their time zone (and your own time when it differs). The "Live opens at..." notice scrolls into view.
  • Out-of-date installed voices now offer "Update voices". The Home Screen app's separate storage is mentioned in the Session ready? card.
  • Trimmed the hiss at the end of some demo recordings (e.g. "Hold your position"). Re-install the demo voices to hear the fix.
  • New lock-screen audio test page for checking what plays on a locked phone.

v70 2026-10-20

  • "Session ready?" check before Live. One card shows your build, when the event starts on your phone's clock, whether the phone's clock is in sync, which recordings are installed, and whether you can lock the screen. Every check only warns; you can always continue.
  • The practice and live screens show a simple "Sound check ✓" line instead of raw diagnostics. Tap it to copy the full details for us.

v69 2026-10-20

  • Easier text events: one space after the time is enough (0:30 Wave left). Two spaces or a tab still work.

v68 2026-10-20

  • Clock check. Everyone's phone follows its own clock. If yours is 5 or more seconds off, the event preview tells you to turn on automatic date & time.
  • One-tap demo voices. The demo offers to install its recorded voices (about 150 KB), so even the demo works with your screen locked.
  • Clearer note when an event's recordings aren't on your phone. The count now matches between preview and practice.
  • "Sound not working?" on the home screen now opens the friendly phone check, not the developer diagnostics.
  • Link previews show a proper card on social media, every page has an icon, and the help page fits small screens. The rating stars are easier to tap.

v67 2026-10-20

  • iPhone fix: text events written like Start: 2026-03-15 2:00 PM (the format the guides use) failed to load in Safari. They now work everywhere.
  • Refreshed guides covering cues vs clips, repeating events, the Go Live window and time zones. This page is new too.

v66 2026-10-20

  • Go Live opens 20 minutes before the first cue. Before that, the app tells you when Live opens and suggests Practice. Going live hours early drained batteries and built a huge mostly-silent audio track.
  • Time zones in text events now work. Start: 2026-11-15T19:00 with Timezone: America/New_York means 7 PM in New York, wherever the phone is.
  • The editor no longer lands an event a month off when its date crosses a month boundary in another time zone.
  • [no-countdown] steps are now truly silent, even when the event has countdowns turned on.
  • Random takes (randomCues) now really pick at random, and the pocket track and the screen play the same take.
  • Links shared from a downloaded copy of the app now point at the public site instead of a broken null/ address.
  • Restarting a past repeating event now repeats for the right length. If the pocket audio track fails to load, the app falls back to live audio instead of hanging.
  • The old experimental Android app has been retired. Conductor is a web app that runs on any phone.

v65 2026-09-10

  • Editor: the style buttons (Normal / Emphasis / Alert) now show a caption when tapped, since phones can't show hover tips.
  • "My Voice (record your own cues)" sits at the top of the cue list, and "record everything at once" is clearly optional.

v63 & v64 2026-09-07

  • Cues and clips. Each step is either a cue (a beep, then people act or speak) or a clip (the phone itself plays a recorded clip: music, crowd murmur, a voice). Clips can be long and can overlap.
  • Set it for the whole event (Mode: clip) or per step ([clip] / [cue]), or use the Playback mode setting and per-step toggle in the editor.
  • A clip-mode demo script shows the idea.

v62 2026-08-22

  • Beam an event by QR code straight from the share screen, phone to phone.
  • The text-size control is reachable during practice and live events.
  • Refreshed FAQ and how-to docs, plus a public "Help from Anywhere" page for remote helpers.

v58 – v61 2026-08-18 – 19

  • Repeating events. Loop the whole script until a set time (RepeatUntil:), a set number of times (Repeat:), or both. Coda: adds a rest between loops.
  • Editor: clone a step in one tap. You're warned when two steps land too close together.
  • Adjustable text size for the whole app.

v53 – v57 2026-08-06 – 12

  • "Get ready to…" in your own voice. Record one "Get ready to" lead. The app stitches it to each cue's recording, and it plays with the phone in your pocket.
  • QR beam for sound packs. Send a pack to a nearby phone as a moving QR code, with no internet needed.
  • Packs are now small MP3s. Each demo script has its own tiny pack.
  • Fixed the pack file picker showing "No items" on iPhone and Android, and demo packs that wouldn't play on iPhone.

v45 – v52 2026-07-06 – 08-04

  • Works with the phone locked in your pocket. Going live builds the event's beeps and recorded cues into one audio track, the only kind of audio phones keep playing when the screen is locked.
  • Record your own cues in the editor ("My Voice") and share them as a pack.
  • Practice rehearses through the same pocket track as the real event.
  • A public Help Us Test page for checking your own phone.

Earlier

v1 – v44 2026-02 – 06

  • The single-file "record player" app. Events travel inside links and QR codes, with no server and no accounts.
  • Editor, practice mode, live mode, circular timeline, optional password encryption, sound packs, tonal countdown beeps, and phone audio diagnostics.
