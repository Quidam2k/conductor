# Cascade: Dual-mode (cue | clip) — additive speaker-clip playback

Dispatch #4489 (pipeline #1724), PROCEED #4491 / plan-back #16565. Refs #1721 (design
rationale: human-out-of-loop, speaker plays audio), #1720 (5-script prototype).

## Goal
ADD a second playback mode — **clip** (speaker plays a full audio clip, no human) —
alongside the existing **cue** mode (cue-beep in earbud → human speaks). Events may mix
both per action. **Hard invariant: cue mode stays byte-for-byte unchanged.**

## Decided trade-offs (Jarvis, from Todd's #1721 conventions)
1. Long-clip OVERLAP: NO guard — clips run past the next trigger and LAYER (music beds +
   emergent crowd-murmur want it). Reversible later via opt-in queue/truncate.
2. GRANULARITY: per-action `mode` + event `defaultMode`. (satisfies "some events have some
   of either kind".) Do NOT restrict to per-event-only.
3. MUSIC BED: a clip-mode action at 0:00 referencing one long bed WAV, overlap allowed. No
   new background-track concept for v1.

## Key finding
Clip playback already exists: `cue`+`pack` (or `randomCues`) already plays a full pack WAV
through the speaker, live AND baked. Clip mode is mostly SUBTRACTIVE around that clip:
no countdown beeps, no trigger beep, no "Get ready to" prep, no TTS trigger word; allow long
clips + layering. Effective mode = `action.mode || event.defaultMode || 'cue'`.
